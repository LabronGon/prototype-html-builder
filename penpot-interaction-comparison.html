摘要：差距不在视觉，而在交互模型

当前原型已完成 MasterGo 风格的 UI 复刻，并在 P12 基础上完成 P13–P19 七批对齐：组与深层选择、变换修饰键、多选 Mixed、字母快捷键并轨、右键分区、评论回复线程、对齐/分布、四角圆角、导出预设、多填充、渐变与图片填充、描边内中外、效果列表（投影/内阴影/图层模糊/背景模糊）。P21 收口后，多描边与虚线、Mixed 覆盖、文本行高/字距/纵对齐/大小写、原型时长与缓动、统一导出对话框（PDF / per-object / 预览进度）、演示 flow 起点 / 缩略图计数 / 分享与登录入口均已落地。剩余差距集中在「布局与填充进阶」「矢量导出精度」与「协作权限」：自动布局与约束、填充混合与层排序、SVG 轮廓化、文件级 .penpot、账号与只读权限模型。

靠拢原则：复制 Penpot 的「交互模型」而不是复制它的视觉皮肤。凡是与现有 MasterGo 视觉 Token 冲突的，以 Penpot 的行为规则与参数为准（快捷键字母、修饰键语义、吸附阈值、缩放范围）；分支性功能（组件、自动布局、插件）不在本轮范围，明确列为「保留差异」。Penpot 为 MPL-2.0 文件级 copyleft：本方案只读取规格、重写实现，不复制源码。

明确保留的差异

以下不是缺口，而是当前产品定位决定的合理差异，不建议为了「像 Penpot」而改。

本地文件保存 vs 服务端自动保存

当前 Ctrl+S / Ctrl+O 基于 File System Access API，单文件可离线打开；Penpot 依赖后端与团队权限。保留现有实现。

Canvas 2D 渲染 vs WASM 渲染器

Penpot 用 Rust/WASM 绘制 + SVG overlay；当前为 Canvas 2D。只对齐交互参数与视觉常量，不迁移渲染架构。

组件 / 变体 / 自动布局
