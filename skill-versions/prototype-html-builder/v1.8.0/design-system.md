## 4. 常用布局配方

### 手机（375×812）

```json
[
  { "type":"instance","comp":"statusbar","x":0,"y":0 },
  { "type":"instance","comp":"navbar","x":0,"y":44,
    "overrides":{"标题":{"text":"页面标题"}} },
  { "type":"instance","comp":"searchbar","x":16,"y":112 },
  { "type":"instance","comp":"tabbar","x":0,"y":729 }
]
```

内容区起点 `y=112`（有搜索）/ `y=100`（无搜索），底部安全区 `y=729`。

### 桌面（1440×900）

- 顶栏 `h=56`：Logo + 菜单 + 右侧头像；
- 侧栏 `w=200`：`side-menu` 实例逐条排布（每条 `y += 40`）；
- 内容区：左右 24 padding，卡片间距 16。

### 大屏（1440×1024，深色）

`theme:"dark"`，画板 `bg:"#0B1220"`，卡片 `fill:"#111A2C"` 描边 `#1E2A44`，标题字号 24–32，数字用 `brand` 高亮。

## 5. 组件使用原则

1. **先查母版**：导航栏/标签栏/按钮/卡片/列表行等通用件一律取内置母版，不要手绘。
2. **只覆盖、不重建**：文案、颜色、图标走 `overrides`；位置走实例 `x/y`。
3. **重复结构自建母版**：同一结构出现 ≥2 次（如设备行、商品卡），在 `components` 里定义一次，再实例化。
4. **状态用色不用新字形**：告警红 `#F53F3F`、成功 `#00B42A`、警告 `#FF7D00`，通过覆盖 `color` 表达。
5. **图标不混套**：一个界面只用 `ep` 或只用 `ant`，避免线性与填充风格混杂；工业/监控场景推荐 `ep`。

## 6. 风格方向与反模板（v1.5）

> 来源：unslop 方法论（Damir Sokolovsky @heydamir，CC BY 4.0）改编。
> **适用边界：用户给了视觉参考图时，一律以参考图为准，本节不覆盖参考图；本节只在「没有视觉参考、从零生成」时作为默认风格基线。**

### 6.1 风格方向五要素（spec 顶层 `direction` 键）

从「产品做什么、给谁用」推导，不从流行趋势推导。写规格时建议先填这五个键：

| 键 | 含义 | 反例（万金油，禁止） |
| --- | --- | --- |
| `product` | 产品一句话：做什么、给谁用 | — |
| `character` | 2–3 个具体气质词，如 `克制, 精确, 偏工业` | 简洁 / 现代 / 高级 / 极简 / 大气 |
| `world` | 产品所属的物质世界，决定中性色倾向与 accent，如「矿山与重型机械」「纸与墨」「夜班仪表」 | 「互联网」「科技感」 |
| `moments` | 1–2 个允许色彩与细节丰富的焦点区，从产品真实内容里选，如「实时监控曲线」「设备台账主表」 | 装饰性横幅、无意义插画 |
| `signature` | 仅此产品会有的签名细节，全屏复用且只出现在该在的地方，如「设备状态呼吸灯」「运单路线线」 | 五个以上花点 |

编译后 `direction` 存入 `__doc` 顶层并摘要进 `aiHint`；`#__ai_view` 头部输出「风格方向」段。AI 改稿未带 `direction` 时沿用原值，显式 `direction:null` 才删除。

### 6.2 默认风格基线（八条）

1. **表面克制**：应用 / 后台的背景、卡片、边框保持中性色（本文件 §1 色板即中性基线）；世界感只进 accent、图表与 moments。背景读出橙/棕/蓝/绿 = 走过头了。
2. **一屏一 accent**：只标主操作、选中态或最关键数字；文本三角色（主 `text1` / 次 `text2` / 弱 `text3`），不要十种微差色。
3. **禁 slop**：色相渐变表面、渐变文字、彩色发光与阴影、emoji 当图标、大写加字距标签、`animate-pulse` 类循环动画、`transition-all`。
4. **圆角嵌套**：内层 = 外层 − 两者间距，且 ≥4；控件 8–10、卡片 12–16、面板 14–20；不是什么都用胶囊。
5. **间距 4px 网格**：同物同尺寸（同类行同高同距）；组内间距 < 组间间距；导航是最密区，行高 32–36、分组「上 24 下 8」。
6. **数字纪律**：`tabular-nums`、全屏一种格式（一个 `$48,210` 配 `$124,860` 就错位）；mock 数据要真实可信，禁 `[X]`、`123,456`。
7. **图表一主多辅**：一屏一张主图表（最大、最用心），其余数据用更小更简的形式（排行细条、短表格）；单 accent 强调当前关注项，确需多系列才多色且一个为主。
8. **模板自检**：把产品名换成别家，这屏还成立吗？成立 = 方向不够，回到 `character` / `world` 加深，而不是加装饰。

### 6.3 审稿九遍序（AI 改稿 / 人工走查顺序）

**间距 → 颜色 → 图标 → 文案 → 字体 → 布局 → 细节 → 视觉 → 动效**，一遍扫全屏再扫下一遍。

- 间距最先：节奏定了其余才可读。
- 文案先于字体：标题长度决定字号与位置。
- 视觉与动效最后：它们应服务于已经成立的版面。
- 文案细则：短标签不带句号、界面文案无感叹号、无「超级赋能/无缝/解锁」类词；改动型指标写清对比基线（`+12% vs 上月`）。
- 动效细则：只保留解释性的动效（hover 变色、按下微缩、弹层淡入上移、数字 tween）；只过渡 color/background/border/opacity/transform 并写明属性；禁动画布局属性（width/height/top/left）。

## 7. 视觉丰富度配方（v1.6，反简陋）

> 解锁 DSL 的 `grad`（渐变）与 `shadow`（投影）两个节点字段后，页面从「纯色平面」升级为「层次界面」。原则一句话：**颜色数量克制，层次与细节丰富**——这不是极简主义，也不是 slop 大杂烩。

### 7.1 两个新字段（spec DSL → 编辑器 fills/effects）

| 字段 | 语法 | 编译产物 | 约束 |
| --- | --- | --- | --- |
| `grad` | `"grad":{"type":"linear","angle":90,"stops":["#3670F7","#5B8CFF"]}`（stops 兼容 `[{color,pos,opacity}]`） | 节点 `fills` 渐变数组（`fill` 保留主色兜底） | **只允许同色系明度/透明度渐变**；色相跨越（ΔH>60°）会被 check-slop 门禁拦截 |
| `shadow` | `"shadow":{"x":0,"y":2,"blur":8,"color":"#101828","opacity":0.06}` | 节点 `effects` 投影 | 只用于**卡片层级**；opacity 上限 0.4；**禁用于文字**（发光） |

### 7.2 反简陋三件套（每个画板必查）

1. **页面底色分层**：工作区页面底用 `#F5F7FA` 级浅灰，内容卡用白底——禁止全屏纯白一张皮。
2. **卡片立体感**：白卡 = 描边 `#E5E6EB 1px` + 圆角 12–16 + 投影 `{y:2, blur:8, color:"#101828", opacity:0.06}`；悬浮层（弹层/下拉）投影加重到 `{y:8, blur:24, opacity:0.12}`。
3. **图形化点缀**：裸文字一律升级——图标配**主色 10% tinted 圆底**（36×36 圆 + 20px 图标）、卡片标题左侧加 **4px 品牌竖条**、关键指标配迷你趋势柱（5–8 根 4px 宽圆角小柱）。

### 7.3 场景化配方速查

| 场景 | 配方 |
| --- | --- |
| 顶栏收边 | 顶栏底缘 2px 品牌渐变线：`angle:0, stops:[主色, {color:主色, opacity:0}]` |
| 监控/视频画面 | 深色底 + 四角取景框（16×16 描边角标）+ 2 根白色 5–7% 透明度扫描线 |
| 告警/状态行 | 左缘 3px 语义色竖条（`rc:[2,0,0,2]`）+ 浅灰底 8px 圆角 + 1px 描边 |
| 表格 | 表头浅灰底 `#F7F8FA`、行斑马纹 `#FAFBFC`、行尾操作列用语义色文字 |
| 选中导航项 | 底 `#EBF1FE`（主色 8%）+ 左缘/图标/文字主色 |
| 胶囊 chip | `radius` 拉满成胶囊 + 1px 描边，状态点 8px |
| 进度/仪表 | 进度条高 6–8px 圆角，轨道用主色 10% 透明度 |
| 空态/成功态 | 大图标 + tinted 圆底 + 标题 + 副文 + 主按钮，占位 120px 高以上 |

### 7.4 与 §6 基线的关系

- §6 ③「禁彩色发光与阴影」管的是**文字发光、彩色 glow、slop 循环动画**；§7 的中性色低透明度卡片投影不受此限。
- §6 ①「表面克制」指**颜色数量**克制（一屏一 accent），不是细节贫瘠；§7 的丰富度全部来自层次（投影/描边/tinted 底/竖条），不新增色相。
- 适用边界不变：**用户给了视觉参考图时以参考图为准**，§7 配方只在无参考或参考图本身简陋时作为下限要求。

## 8. 布局栅格与对齐系统（v1.7）

> 对齐不是审美偏好，是可静态校验的硬约束。交付前必须跑 `node scripts/check-layout.mjs <产物.chao.html> --strict` 并 PASS——**「差一点对齐」（≤4px 的漂移）比明显不对齐更致命**，因为它看起来像失误。

### 8.1 桌面栅格（1440 基准）

| 层 | 规则 |
| --- | --- |
| 页边距 | 内容区距画板边缘 **24px**（含底栏安全区） |
| 侧栏 | 固定宽 200px；内容区从 `侧栏宽 + 24` 起（1440 布局即 x=224） |
| 列结构 | 内容区按 **2–3 列**划分，列宽全画板统一；列间距（gutter）**16 或 24px**，同一画板只用一个值 |
| 卡片 | 同列卡片**等宽**（= 列宽）；同一行的卡**等高**；卡间距 = gutter |
| 卡内边距 | 统一 **16px**（紧凑场景 12px，同一画板不混用）；卡头标题距卡顶 16px |
| 纵向节奏 | **8px 栅格**：所有 y 坐标落在 8 的倍数上（允许 ±2 微调文字视觉居中）；组内行距 8、组间距 16–24，同一画板各卡遵循同一节奏 |

### 8.2 对齐规则（check-layout 逐条对应）

1. **同列同 x**：同一卡片/同一列内的元素左缘必须精确相等——标签、值、输入框、按钮全链对齐到卡 padding 线。4px 漂移（1120 vs 1124）= 失误。
2. **数值右对齐**：表格/遥测的数值列用 `align:'right'` + 固定 `w`（x = 卡右缘 − padding − w），禁止靠手调 x 模拟右对齐。
3. **行距一致**：同类元素序列（表格行、指标行、日志行、chip 行）行距必须相等；不同类元素之间（标题→内容）的组间距允许更大，但同一画板内同类组的组间距要一致。
4. **实例用声明尺寸**：组件实例的宽度由母版决定；同一母版的实例在网格中宽度天然一致，不要用子树文本溢出撑宽。
5. **居中即对齐**：高度不同的元素（图标底 40 / 按钮 32）垂直居中于同一中线时顶缘天然不等——这是合法的，对齐的是**中心线**。

### 8.3 build 工作流

```
build → check-layout（默认 WARN 模式看全量清单）→ 修 spec 坐标 → check-layout --strict PASS → 交付
```

- 常见修复：统一列锚点 x、值列改右对齐、行距吸附 8px 栅格、系列宽度改由母版控制。
- 门禁按 tol=4 判「近失对齐」；有意错位（如折叠面板缩进）≥TOL 即不报。

## 9. 首版页面规范（v1.8，PC / APP 双基线，首版锁定）

**原则**：第一次生成界面前先把规范定义清楚，并在 spec 里声明 `platform`；build 写入 `__doc.pageSpec`（`locked:true`）后，**第一版输出即锁定**。后续改稿、实现、追加页面必须沿用同一端型与规范，不得静默切换（`apply-doc.mjs` 在锁定状态下拒绝换 platform）。用户给了视觉参考图时以参考图为准——覆盖视觉细节，但不改变端型与锁定状态。

| 系统栏 | 状态栏 24dp；顶部应用栏 56dp；底部导航 56dp；手势区 16dp | `statusbar` / `navbar` / `tabbar` 母版 |
| 触控 | 触控目标 ≥48dp；列表行 ≥56dp；按钮最小 64×40dp | 热区 rect 不小于该尺寸 |
| 字号 | 14sp 正文 / 12sp 辅助 / 16sp 小标题 / 20–24sp 页面标题 | Material type scale |
| 色彩 | Material 3 color roles（primary / on-primary / surface / surface-variant / outline / error），主色与 PC 端保持一致映射 | `design-kit.json` 做等价 Token |
| 组件 | 顶部应用栏、底部导航、FAB 56dp、Snackbar、卡片 8–12dp 圆角、列表 divider | 母版 + `proto` 串联页面 |
| 交互 | 页面切换左滑/右滑；弹层用底部 sheet；返回用系统返回或左上角返回 | `proto.anim` |

### 9.3 锁定与校验

1. `spec.platform` 缺省 = `pc`，build 会输出提示；**APP 原型必须显式写 `"platform":"app"`**。
2. `__doc.pageSpec` 字段：`version` / `locked` / `platform` / `standard` / `viewport` / `grid` / `controls` / `token` / `pages[{name,platform,standard,viewport}]`。
3. `#__ai_view` 头部输出「=== 首版页面规范（pageSpec，已锁定）===」段；GUIDE v1.6 / NOTICE / `meta` / `aiHint` 四处规范入口同步。
4. `apply-doc.mjs` 保护性合并：AI 未带 `pageSpec` 沿用原值；显式 `null` 才删除；锁定状态下换 `platform` 直接拒绝。
5. 编辑器保存（`persistDoc`）原样带回 `pageSpec` / `direction`，人工精调不会抹掉首版规范。
6. `validate-doc.mjs` 校验 `pageSpec` 结构；缺失只提示、不阻断旧文件。
